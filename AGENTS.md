# Project Architecture Rules
- Keep "מוצרים שאתם עשויים לאהוב" rules in one browser-safe module (src/lib/related-products.ts): a never-suggest handle set plus a prefix search (`title:<family>*`), because Shopify matches whole words only and an exact `title:עגיל` returns a pool of two products. This keeps suggestion pools real without touching Shopify data.
- Share discount-link activation through the persisted cart store; keep one coupon per mutation, refresh Shopify-returned allocations after cart changes and validate again before opening the existing checkout, so no client percentage or stale cart price determines the charge. Discount-combination eligibility remains a Shopify-admin rule.
- Keep Shopify-style /products/$handle URLs as permanent local redirects to the shared /product/$handle template, using the existing handle registry and preserving query parameters; catalog links must retain product destinations without changing commerce identities or domains.
- Keep verified storefront identity in one browser-safe module and emit a single linked store/website JSON-LD graph on the homepage; shared contact links consume the same identity to prevent contradictory business attribution.
- Centralize Meta browser events and advertising permission in browser-safe modules mounted once in the root; successful shared cart mutations report additions and product rendering reports views. Shopify owns InitiateCheckout (verified in checkout) and Purchase; never also send these from this site or add CAPI without verified shared event IDs, preventing false or duplicate sales.
- Paginate category and product-detail reads through the browser-safe Shopify catalog helper and deduplicate only original identities; batches must not truncate products, variants or media.
- Generic product media uses Shopify variant-image relationships, never ALT-based color inference; only exact selected combinations may enter the cart, preserving inventory identities.
- Reuse the existing product template for onboarding and keep generic fallbacks free of material, durability, skin and packaging promises; approved product-specific exceptions stay separate.
- Render Shopify descriptionHtml verbatim in the product page full-description area via DOMPurify-sanitized HTML; preserve the complete plain-text fallback there too. Never derive a purchase summary from Description or override it from internal copy tables; without a dedicated short-description field omit only the summary, so Shopify stays the single source of truth without duplicated opening paragraphs.
- Order all categories by Shopify creation date descending through the paginated catalog query and browser-safe ordering helper; merged products inherit their newest source creation date, avoiding manual priorities or commerce mutations.
- Preserve imported supplier variant identities for renamed rings and map their public slugs in the handle registry; this avoids duplicate products and broken inventory synchronization.

- Identify home-delivery-only storefront items through `HOME_ONLY_HANDLES`; this keeps product and cart shipping behavior consistent without exposing suppliers.
- Map product media to Shopify option values explicitly when variant-specific ordering matters; resolve Guy's media from live SKU-linked variant images rather than saved CDN filenames so supplier reimports cannot break its gallery. Alt text remains accessibility content, not business logic.
- Resolve Lior colour galleries in the browser-safe lior media module using live SKU-linked images and its explicitly verified silver model assignment; retain the approved uploaded original only as a sync-removal fallback, preventing incomplete hardcoded galleries and cross-colour media.
- Share approved product-specific media between the product gallery and category card through a browser-safe media module to prevent inconsistent photo selection.
- Eitan card and gallery share the eitan module: merge live Shopify media in source order with all approved supplemental photos using URL-identity deduplication; select colours via live SKU links and the verified catalog close-up assignment, never replace source media with a closed list. Dim uses generic live variant media for the same reason.
- Generic products and Efrat render card and gallery images in Shopify media order with no per-handle index overrides, so reordering images in Shopify takes effect without code changes; other asset-based composite products keep their media modules. Exception: Efrat's Shopify variants all link to the same image, so its colour→media mapping lives in VARIANT_IMAGES using live Shopify CDN URLs (never saved assets); the card still follows Shopify media order.
- Keep verified men's bracelet specifications in a browser-safe product module, separate from live Shopify prices and availability, to prevent unsupported generic claims.
- Scope men's bracelet card copy through the category context and a SKU-keyed presentation module with a generic short-name fallback; this preserves full product-page titles and applies the layout to future category items without mutating commerce data.
- Assemble Shay as a presentation-only product from both live source products with verified ID/SKU/color mappings; retain original variant IDs, live prices and availability so checkout and external inventory identities remain unchanged.
